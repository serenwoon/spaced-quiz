# spaced-quiz

마크다운 노트에 적어둔 문항을 터미널에서 간격 반복으로 푸는 도구입니다.

만든 이유는 단순합니다. 퀴즈를 스물일곱 편 써놓고 스물여섯 편을 한 번도 안 풀었거든요. 자료를 만드는 일과 그걸 실제로 여는 일은 완전히 다른 일이더군요.

## 진도를 노트 옆에 둡니다

간격 반복 도구는 보통 진도를 자기 데이터베이스에 넣습니다. 옵시디언 플러그인도 그렇고요. 그런데 그 파일은 대개 `.gitignore` 대상이라 기기를 옮기면 따라오지 않습니다. 맥에서 복습해도 윈도우는 모릅니다.

그래서 진도를 노트 폴더 안 마크다운 표에 씁니다. 노트를 git으로 옮기는 사람이면 진도도 같이 따라갑니다.

파일 하나에 키 순으로 정렬해 둡니다. 양쪽에서 서로 다른 문항을 풀면 git이 알아서 합치고, 같은 문항을 같은 날 양쪽에서 풀었을 때만 충돌이 납니다. 그때는 한 줄 고르면 됩니다.

원본 퀴즈 파일은 건드리지 않습니다. 문항 옆에 상태를 박으면 원본이 더러워지고, 두 기기가 같은 파일을 고쳐 충돌이 잦아집니다.

## 채점은 사람이 합니다

문항이 서술형이면 자동 채점이 불가능합니다. 되는 척하면 학습이 망가지고요. 말해보고, 펼치고, 스스로 누릅니다.

| 누른 것 | 다음 등장 |
|---|---|
| 틀림 | 내일. 간격과 연속 정답이 초기화됩니다 |
| 애매 | 간격 그대로. ease만 깎입니다 |
| 맞음 | 1일 → 6일 → 그다음부터 `간격 × ease` |

애매에서 간격을 안 늘리는 것이 SM-2와 다른 점입니다. 답을 펼쳤을 때 "아 맞다"는 떠올랐다는 뜻이고 "아 그렇구나"는 못 떠올렸다는 뜻인데, 후자를 맞은 것으로 쳐서 간격을 벌리면 다음에 만날 때는 더 안 떠오릅니다.

## 문항 수를 주장하지 않습니다

제 노트 폴더의 문항 수는 세는 방법마다 달랐습니다. 목차가 선언한 값이 723, 각 파일 머리말의 `count:` 합계가 781, 답 블록 수가 722, 문항 헤딩 수가 686이었어요.

무엇이 맞는지 정하는 건 이 도구가 할 일이 아닙니다. 긁힌 것만 세고 그 수를 화면에 띄웁니다.

## 절반만 긁히는 파일을 알립니다

문항이 하나도 안 긁힌 파일은 건너뛴 것으로 보고합니다. 건너뛸 파일 목록을 손으로 적어두는 방식은 쓰지 않았습니다. 목록을 적으면 목록 밖의 파일이 조용히 사라지니까요.

더 위험한 건 절반만 긁히는 파일입니다. 아예 안 긁히면 건너뛴 것으로 드러나는데, 일부만 긁히면 그 파일이 도는 것처럼 보이면서 나머지가 조용히 사라집니다. 실제로 예순아홉 문항짜리 파일에서 열 개만 긁힌 적이 있습니다.

그래서 머리말에 `count:`가 있으면 긁힌 수와 대조하고, 안 맞으면 양쪽 수를 나란히 보여줍니다. 어느 쪽이 맞는지는 말하지 않습니다.

## 기대하는 형식

```markdown
## A. 기본

### Q1 🟡
질문 본문. 여러 줄이어도 됩니다.

> [!success]- 답
> 답 본문.
> 📎 [[출처 노트]]
```

헤딩 뒤에 무엇이 붙든 받습니다. 난이도 표시를 달거나 `**최종**` 같은 꼬리표를 붙이는 일이 흔한데, 거기서 엄격하면 파일마다 마지막 문항 하나씩을 조용히 놓칩니다. 실제로 그렇게 놓쳤습니다.

접힘 콜아웃의 이름은 보지 않습니다. `[!success]-` 뒤가 "답"이든 "Answer"든 상관없습니다.

문항 키는 파일 이름의 앞번호와 문항 번호를 이은 `61-1#Q7` 꼴입니다. 그래서 파일 이름의 앞번호를 바꾸면 그 파일 진도가 끊깁니다.

## 돌리는 데 필요한 것

파이썬 3.10 이상. 바깥 라이브러리는 안 씁니다.

```bash
python -m src --dir fixtures/sample --stats     # 예시로 먼저 확인
python -m src --dir <노트 폴더>                  # 오늘 세션 (기본 10문항)
python -m src --dir <노트 폴더> --count 5
python -m unittest discover -s tests            # 시험 48개
```

진도 파일은 기본으로 `<노트 폴더>/_progress.md`에 씁니다. `--ledger`로 다른 데를 가리킬 수 있고, 환경변수 `QUIZ_DIR`과 `QUIZ_LEDGER`도 봅니다.

`fixtures/sample`은 형식을 보이려고 지어낸 예시입니다. 문항이 없는 파일과 머리말 수가 안 맞는 파일이 섞여 있는데, 일부러 그렇게 뒀습니다.

## 만들다 낸 사고

진도 파일 경로의 기본값을 `def save(states, path=LEDGER)`처럼 인자에 묶어뒀습니다. 파이썬은 기본값을 함수 정의 시점에 한 번 계산하기 때문에, 나중에 모듈 상수를 바꿔도 안 먹습니다.

시험이 임시 경로를 가리켰다고 믿었는데 실제로는 진짜 진도 파일에 가짜 채점 네 건이 들어갔습니다. 파이프로 흘려넣은 값이지 제가 실제로 떠올린 게 아니었고요.

기본값을 `None`으로 두고 호출 시점에 읽도록 고쳤습니다. 그 자리를 붙드는 시험도 넣었습니다.

같은 종류를 하나 더 냈습니다. 파트 이름을 문항이 닫힐 때 읽고 있었는데, 그 시점에는 이미 다음 절 헤딩을 지난 뒤라서 각 파트의 마지막 문항이 다음 파트 이름을 달았습니다. 예시 픽스처를 만들다 드러났습니다.
